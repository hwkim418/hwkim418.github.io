CCTV IP Conflict Causing Intermittent Video Loss

February 15, 2026
Network · CCTV · IP Conflict · ARP · Cisco

Overview

A newly installed IP-CCTV camera experienced intermittent video loss, with short, repetitive interruptions lasting approximately 5–20 seconds before automatically reconnecting.

The initial suspicion was PoE instability or an NVR software issue. However, the interruption pattern did not match a power-related reboot, which would normally cause a longer outage, nor did it resemble a sustained software malfunction.

Further investigation revealed inconsistent ARP mappings for the affected IP address. The MAC address associated with the camera's IP changed intermittently, indicating that multiple devices were responding to the same IP address.

Root Cause

A newly installed CCTV camera was configured with a duplicate static IP address. Two devices were responding to the same IP, causing unstable ARP-to-MAC mappings and intermittent video connectivity.

Why It Matters

IP conflicts can cause unpredictable service disruption even when the physical network itself is stable.

In environments using static IP addressing, duplicate addresses can result in traffic being intermittently directed to different devices as ARP mappings change.

  • ARP entries may alternate between different MAC addresses.
  • Traffic may intermittently reach the wrong endpoint.
  • Applications may disconnect and reconnect repeatedly.
  • Critical systems can experience service interruptions.

In security environments, even short periods of CCTV video loss can affect monitoring, evidence retention, compliance, and operational safety.

Environment

  • Camera Model: LTS CMIP3382WI-28SDL
  • Camera: 8MP, 2.8 mm lens, IR, built-in microphone and speaker
  • Video: 8MP continuous recording
  • Core Switch: Cisco Catalyst 9500 — Layer 3 / Inter-VLAN routing
  • CCTV Access Switch: Cisco Catalyst 9200L PoE+
  • Edge Switch: Production-floor PoE switch supplying camera power
  • Network Flow: C9500 Core → C9200L CCTV Access → IDF PoE Switch → IP Camera
  • Issue Type: Duplicate static IP / ARP instability
  • Impact: Intermittent CCTV video loss

Troubleshooting Process

1. Check the ARP Entry for the Camera

The camera's IP address was known, so the investigation began at the C9500 core switch by checking which MAC address was associated with that IP. 

C9500_BB# show arp | include 192.168.50.45

Example output: 

Internet  192.168.50.45  2  aaaa.bbbb.cccc  ARPA  Vlan50

When the ARP entry was checked again, the same IP address appeared with a different MAC address.

Example output: 

Internet  192.168.50.45  1  dddd.eeee.ffff  ARPA  Vlan50

What to look for: A statically addressed CCTV camera should normally maintain the same IP-to-MAC relationship. In this case, the same IP address was appearing with two different MAC addresses.

What it tells us: This was strong evidence that two devices were using 192.168.50.45.

2. Trace the Two MAC Addresses

The next step was to determine where the two MAC addresses were located in the network.

Each MAC address was checked separately in the MAC address table.

MAC address 1: 

C9500_BB# show mac address-table address aaaa.bbbb.cccc

MAC address 2: 

C9500_BB# show mac address-table address dddd.eeee.ffff

Example output for one MAC address: 

Vlan    Mac Address       Type        Ports
```

---

50      aaaa.bbbb.cccc    DYNAMIC     Te1/0/1
```

What to look for: The interface in the final column shows which direction the switch uses to reach that MAC address.

3. Confirm the Duplicate IP

The investigation confirmed that the newly installed CCTV camera had been configured with a static IP address that was already in use by another network device.

Advanced IP Scanner was also used as an additional verification step while investigating the affected address. 

192.168.50.45

What to look for: Compare the devices, MAC addresses, and configured IP information to determine whether the same static IP has been assigned more than once.

What it tells us: The ARP behavior and endpoint investigation confirmed that the newly installed camera and another existing network device were using the same IP address.

Resolution

The duplicate static IP configuration was corrected by assigning an unused IP address to the incorrectly configured device.

The ARP cache was then cleared so that the network could relearn the correct IP-to-MAC mapping. 

C9500_BB# clear arp

The ARP table was checked again to verify that the affected IP address remained consistently mapped to the expected MAC address. 

C9500_BB# show arp | include 192.168.50.45

Verification: The affected IP remained consistently associated with the expected MAC address after the duplicate configuration was corrected. CCTV video was also monitored, and the repetitive 5–20 second interruptions were no longer observed.

Lessons Learned

  • Check ARP table stability early when troubleshooting intermittent connectivity involving statically addressed devices.
  • A changing MAC address for a fixed IP address can be a strong indicator of a duplicate IP configuration.
  • Static IP environments require careful IP address management and documentation to prevent address duplication.
  • Short, repetitive service interruptions do not necessarily indicate a physical-layer or PoE problem.
  • Combining Layer 3 ARP information with Layer 2 MAC address-table tracing can help isolate the physical location of conflicting endpoints.
