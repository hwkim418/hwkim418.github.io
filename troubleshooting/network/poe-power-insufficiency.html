PoE Power Insufficiency Causing an AP to Operate in 2.4 GHz Only

January 29, 2026
Network · Wireless · PoE · Cisco · Aruba

Overview

Several wireless access points were observed operating only on the 2.4 GHz band while their 5 GHz radios were disabled.

The initial suspicion was an RF configuration or wireless controller issue. Further investigation, however, showed that the problem originated at the access switch.

The access point was receiving power, but the switch port was not allocating enough PoE power for the AP to operate with its full radio capabilities.

Root Cause Insufficient PoE power allocation on the access-switch port caused the Aruba AP to enter a degraded operating mode, disabling its 5 GHz radio while continuing to operate on 2.4 GHz.

Why It Matters

PoE does more than simply determine whether a network device powers on.

Modern enterprise wireless access points may dynamically disable higher-power features when the available PoE budget falls below the required threshold.

  • 2.4 GHz radio requires less power.
  • 5 GHz radio requires additional power.
  • Insufficient PoE can place an AP into a degraded mode.

As a result, what initially appears to be an RF or controller problem can actually originate from a Layer 1 electrical constraint.

Environment

  • Core Switch: Cisco Catalyst 9500 16X 10G
  • Access Switch: Cisco Catalyst 9200L 24 PoE+
  • Access Point: Hewlett-Packard Aruba AP-535
  • Wireless: 802.11ax, 2.4 GHz / 5 GHz
  • Issue Type: PoE budget / power negotiation
  • Impact: Partial wireless service degradation — 5 GHz unavailable

Troubleshooting Process

1. Identify the Affected Device

The first step was to map the IP address of the affected access point to its MAC address. 

C9500_BB# show arp | include 192.168.123.123

Example output:

Internet  192.168.123.123  2  6026.efc0.78b8  ARPA  Vlan123

Why start from the C9500 core switch? At the beginning of the investigation, the AP's IP address was known, but its physical access-switch port was not. Because the C9500 acts as the Layer 3 gateway for the network, its ARP table can be used to map the AP's known IP address to a MAC address. From there, the MAC address table and CDP can be used to trace the network path downstream until the access switch and physical port connected to the AP are identified.

What to look for: Identify the MAC address associated with the AP's IP address. In this example, the MAC address is 6026.efc0.78b8.

Next, use the MAC address table to determine where that MAC address is being learned. 

C9500_BB# show mac address-table address 6026.efc0.78b8

Example output:

Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
123     6026.efc0.78b8    DYNAMIC     Te1/0/1

What it tells us: The AP is not directly connected to the core switch. Its MAC address is being learned through Te1/0/1, so the next step is to identify the downstream switch connected to that interface.

2. Locate the Access Switch

Cisco Discovery Protocol (CDP) can be used to identify the neighboring switch connected through the interface found in the previous step. 

C9500_BB# show cdp neighbors
C9500_BB# show cdp neighbors detail

Example output:

Device ID        Local Intrfce     Platform        Port ID
P1_Incoming_01   Te1/0/1           C9200L-24P      Gi1/1/1

What to look for: Match the interface identified from the MAC address table with the corresponding CDP neighbor.

What it tells us: The affected AP can now be traced downstream to the access switch P1_Incoming_01.

3. Verify PoE Status on the Access Switch

After accessing the edge switch, inspect the PoE status and power allocation for connected devices. 

P1_Incoming_01# show power inline

Example output:

Interface  Admin  Oper       Power   Device
---------  -----  ---------  ------  ----------------
Gi1/0/13   auto   on         15.4 W  Ieee PD

What to look for: Do not stop after confirming that Oper shows on. Also check how much power is actually being allocated to the device.

In this case, the important observation was that the AP was receiving power, but the available allocation was insufficient for full operation.

What it tells us: This explains why the AP could remain online while still operating with reduced functionality. The problem was not a complete PoE failure; it was insufficient available power.

4. Verify the Physical Switch Port

The AP's MAC address was then checked on the access switch to identify the exact physical interface connected to the device. 

P1_Incoming_01# show mac address-table address 6026.efc0.78b8

Example output:

Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
123     6026.efc0.78b8    DYNAMIC     Gi1/0/13

What to look for: The final column identifies the physical switch port on which the AP's MAC address is being learned.

What it tells us: The affected AP is connected to Gi1/0/13. We can now inspect and modify the correct physical interface rather than making changes elsewhere on the switch.

5. Review the Interface Configuration

The interface configuration was reviewed before making any changes. 

P1_Incoming_01# show run interface Gi1/0/13

Example output:

interface GigabitEthernet1/0/13
 switchport access vlan 123
 switchport mode access
 power inline auto
 spanning-tree portfast

What to look for: Review the port's PoE configuration together with its VLAN and other interface settings. The goal is to verify that the correct interface has been identified and determine whether an explicit PoE allocation is configured.

What it tells us: With the physical port confirmed and insufficient PoE identified, the issue can be addressed at the interface level.

Resolution

The switch interface was configured to explicitly allocate 30 watts of PoE power to the access point. 

P1_Incoming_01# configure terminal
P1_Incoming_01(config)# interface Gi1/0/13
P1_Incoming_01(config-if)# power inline static max 30000
P1_Incoming_01(config-if)# end
P1_Incoming_01# write memory

After the change, the PoE status should be checked again. 

P1_Incoming_01# show power inline

Verification: Confirm that the AP is receiving the expected power allocation, then verify from the wireless side that the 5 GHz radio is operational again.

This provided sufficient power for the connected access point to operate without the previous PoE limitation.
