Numeric Parsing Failure in Unit Price Field

February 27, 2026
Application · Input Validation · API · Database · Troubleshooting

Overview

Users were unable to save purchase requests when entering comma-formatted values in the Unit Price field.

For example, 5,221,000 failed with the message Input string was not in a correct format., while 5221000 saved successfully.

Root Cause

The UI transmitted the formatted value 5,221,000 directly to the API. The backend attempted to parse the string as a numeric value without removing the thousand separators or applying culture-aware parsing.

The conversion therefore failed in the application layer before the value could be committed to the database.

Environment

  • Application: Internal Purchase / Import Items Web Application
  • Field: Unit Price
  • Backend: Application Server + Relational Database
  • Database Column: INT / DECIMAL

Troubleshooting Process

1. Reproduce the Issue

The same numeric value was tested with and without thousand separators. 

5221000    → Success
5,221,000  → Failure

What it tells us: The numeric value itself was valid. The failure was associated with its formatted representation.

2. Inspect the Browser Network Payload

The request payload was inspected using the browser's developer tools. 

"5,221,000"

What it tells us: The commas were not removed by the UI. The formatted string was being sent directly to the API.

3. Review Backend Parsing

Backend processing showed direct string-to-numeric conversion without comma stripping or culture-aware input handling.

What it tells us: The application expected a raw numeric value but received a formatted string containing thousand separators.

4. Verify the Database Layer

The database schema was reviewed to confirm that the Unit Price column used a numeric data type.

The failure occurred during application-side parsing before the database commit, confirming that the database was not the source of the parsing error.

Resolution

The issue requires numeric input to be normalized before backend numeric conversion. Formatted values such as 5,221,000 should be converted into a representation the application can safely parse before database processing.

Lessons Learned

  • UI formatting and backend input expectations must remain consistent.
  • Numeric input should be normalized or parsed appropriately before conversion.
  • Comparing successful and failed inputs is an efficient way to isolate formatting-related problems.
  • Browser network tools can quickly reveal whether unexpected values are being transmitted to an API.
  • Identifying the layer where a failure occurs prevents unnecessary database troubleshooting.
